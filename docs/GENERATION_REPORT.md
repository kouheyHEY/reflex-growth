# 二作目生成レポート

## 入力

ユーザー入力は「反射神経測定ゲーム + 育成ゲーム」というテーマのみ。タイトル、ループ、測定方式、成長方式、技術、時間、公開先は未指定だった。

## 補完した設計

テーマを「待つ → 合図 → タップ → 実測値 → XP → 即時再挑戦」へ分解した。測定ゲームとしての信頼性を守るため、育成による判定猶予や数値補正は採用せず、成長はレベル、光の段階、連続数、演出へ限定した。

補完値はすべて `RECOMMENDATION` または `ESTIMATE` とし、市場調査は `not_run` のまま保存した。

## 一作目から再利用できたもの

- 入力・補完値・事実の出典分離
- Player Agency Contract
- Responsiveness Contract
- Loop Continuity Contract
- Implementation Task形式
- 自動評価と人評価の分離
- 必須アプリレビューゲート
- 公開プレビューと自動公開OFF
- 外部依存のないPC・スマホ共通ビルド

一作目では「MAX到達とパンチ実行」、二作目では「合図表示と反応記録」をPlayer Agency Contractで分離した。一作目では「破壊演出と次チャージ」、二作目では「結果表示と次試行」をResponsiveness Contractで分離した。ゲーム固有コードを共有しなくても、契約の意味は再利用できた。

二作目の試遊では、次試行が0msで開始可能でも、再開専用タップが1回必要ならループの摩擦が残ると判明した。成功タップを継続意思として再利用するLoop Continuity Contractを追加し、「操作可能時間」と「必要入力数」を別々に検査する。

## 二作目で新しく必要になった境界

### Measurement Integrity

測定対象、開始イベント、終了イベント、単位、補正の有無を明示する。育成や難易度が測定結果を書き換えていないことをテストする。

### Growth Integrity

報酬頻度、レベル到達性、視覚段階、永続化を検査する。ただし「育ったと感じるか」は人レビューに残す。

この2つは、今後のスコアゲーム、学習ゲーム、フィットネスゲーム、放置・育成ゲームにも一般化候補となる。

- 未宣言の自動測定確定を拒否

## 人が確認すること

- 光の合図を迷わず認識できるか
- 数値が体感から大きくずれていないか
- 待ち時間が緊張感か退屈か
- 成長段階が再挑戦理由になるか
- 強い発光と反復音が快適か
- 数分間遊んだときの疲労

自動レビューのpassは、公開承認や面白さの保証ではない。
