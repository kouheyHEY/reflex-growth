# Loop Continuity Contract

反復ループの結果後に、同じ継続意思をもう一度入力させていないかを記録・検査するためのジャンル非依存契約です。

## Responsivenessとの違い

Responsiveness Contractは「次の操作が何ms後に可能か」を扱います。しかし0msで操作可能でも、再開ボタンや再タップが必要なら操作摩擦は残ります。

Loop Continuity Contractは以下を扱います。

- 次ループ開始に新しい判断があるか
- 結果を確定した入力を継続意思として再利用できるか
- 追加の再開入力が何回必要か
- 成功・失敗・キャンセルのどこまで自動継続するか
- 結果表示を次ループと並行できるか

## 自動継続してよい条件

1. 前の入力がプレイヤー自身によるもの
2. 次の状態へ進むことに新しい選択やコストがない
3. 自動化するのは次の準備状態まで
4. 次の重要結果は改めてプレイヤー入力で確定する
5. 結果と次状態の両方が理解できるフィードバックがある

## ジャンルをまたぐ例

- 反射ゲーム: 成功タップ → 結果を残して次の合図待ち
- エンドレスアクション: 敵撃破 → 次の敵を即出現、攻撃自体は手動
- パズル: 手を確定 → 消去演出中に次盤面を準備
- リズムゲーム: 1ノート判定 → 次ノート待機
- 学習ドリル: 正答確定 → 解説を残して次問を準備

購入、分岐選択、リソース消費、公開など新しい意思決定を伴う場合は自動継続しません。本作では成功のみ自動継続し、早押しと時間切れは内容を認識するため手動再開のままです。
